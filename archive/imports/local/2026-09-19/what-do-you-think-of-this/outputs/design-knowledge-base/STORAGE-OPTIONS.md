# Cloud home for the growing knowledge base

Recommendation prepared 19 September 2026. Status: proposal; no cloud migration performed and no destination account selected.

## Recommendation

Updated recommendation after the user emphasized visual browsing and clips: use Notion as the main research home. Organize a Research Inbox, a gallery of sources/clips, and a maintained playbook. Preserve source URLs, dates and evidence status. This supersedes the initial GitHub-first recommendation; destination selection and migration remain pending.

GitHub is still suitable for later skill/plugin releases and selected portable exports. It displays Markdown as formatted documents, including linked sections and images, rather than requiring readers to inspect raw data. Its repository interface remains oriented around files and revisions.

Keep MindLeverX's actionable feedback in the MindLeverX development repository, for example under `docs/reviews/`. The separate handoff prepared in this workspace is intended for that coding session. The knowledge base can retain historical case-study examples, but should not become a second active product backlog.

## Comparison

| Option | Documented capabilities | Judgment for this collection |
|---|---|---|
| GitHub | Private repositories, file history, Markdown preview, browser editing, issues for ideas/tasks | Good future home for packaged technical assets and versioned exports; less aligned with the newly emphasized visual clipping workflow |
| Notion | Page databases with properties/views, desktop/mobile web clipping, Markdown/CSV export | Recommended main research interface given the user's clarified preference; exporting does not instantly recreate a workspace |
| Google Drive/Docs | Cloud file access and sharing; current Docs guidance supports editing .md files while retaining the format | Strong general file/document home; a curated index and a separate packaging/version workflow would still be our responsibility |

## Proposed continuing-research workflow

Capture a question/source → inspect it → record scope and limits → connect it to a finding or principle → review the change → incorporate it into the maintained collection.

In Notion, proposed views are: a gallery for browsing sources, a table for inspecting source/date/status fields, and a reading list for the playbook. These are planned organization choices, not an already created workspace. The existing check dates and evidence statuses should survive every update. Skills/plugins would use a selected export of the maintained material.

Start with one canonical home in Notion if that choice is confirmed. Keep deliberate portable exports for reuse; do not assume automatic synchronization with GitHub or Drive. MindLeverX implementation feedback remains separate in the coding project. This architecture is a proposal, not an existing integration.
