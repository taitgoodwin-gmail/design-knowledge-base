# Reuse plan

This is a packaging proposal. No skill or plugin is installed by this knowledge base.

| Future form | Use this material | Additional work at that stage |
|---|---|---|
| Design-review skill | Playbook, evidence policy, findings template, source catalog | Define triggers, review workflow, output contract and realistic evaluation cases using the current skill-creation guidance |
| Design-teaching skill | Playbook, worked cases, research worksheet | Define learner-level adaptation and feedback exercises; distinguish teaching examples from measured outcomes |
| Plugin | Knowledge base plus selected skills and optional tools | Choose capabilities, package using current plugin specifications, test discovery and tool behavior |
| Knowledge app/wiki | Markdown library and readable catalogs | Choose destination and access model; import content and verify links |
| Search or retrieval service | JSON source/finding records and Markdown sections | Preserve source IDs, dates, status and applicability in retrieved answers; test retrieval before relying on it |

## Recommended architecture

Maintain one knowledge collection. Future skills describe how to use it; plugins distribute chosen capabilities around it. Keep project-specific findings optional so the reusable method does not assume every site is MindLeverX.

Suggested workflow for a future review skill: inspect the actual interface → establish task and context → identify relevant requirements/guidance → record observation and alternative explanations → propose a change → select appropriate verification → deliver traceable findings.

Use a release snapshot for a distributable package rather than an undocumented copy. Record the knowledge-base version in the package and recheck the relevant source guidance. Installation, external publication and actual project modifications are separate future actions; this document creates no new approval process.
