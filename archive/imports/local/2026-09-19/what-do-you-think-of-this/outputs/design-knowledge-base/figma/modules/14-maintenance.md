# Change detection, documentation conflicts and entitlements

Checked 2026-09-20. Evidence: documentation synthesis; hands-on scope is separately recorded.

## Documented behavior

Best-practice guides are useful workflow references but may retain historical techniques. Current Help Center documentation and observed UI should resolve operational questions; conflicts must remain visible until tested. Release notes identify changes that require targeted rechecks. A directory entry, marketing claim, documentation read and hands-on result are different evidence levels.

Sources: [S01: Best Practice Guides](https://www.figma.com/best-practices/guides/), [S02: Figma Design Help Center](https://help.figma.com/hc/en-us/categories/360002042553-Figma-Design), [S36: Release notes](https://www.figma.com/release-notes/).

## Our implementation practice

- Update check dates only after a new check.
- Track product, plan/seat, platform, selection and UI conditions for every control record.
- Recheck beta features, credits and access before consequential use.
- Do not automatically replace unresolved conflicts with the more convenient claim.
