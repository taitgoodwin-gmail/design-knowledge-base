# Maintenance practice

GitHub is the maintained home for this knowledge edition. Notion/local originals are preserved as dated imports; this migration creates no two-way synchronization or scheduled automation.

1. Capture new material in inbox/ with origin, date and scope. Do not present it as authoritative until reviewed.
2. Decide whether it is general guidance, platform behavior, project evidence or a hypothesis.
3. Add/update source records with stable IDs and provenance. Preserve old check dates; recheck relevant official guidance before consequential use.
4. Edit the canonical maintained document, link other indexes to it, and retain superseded claims in history.
5. Record meaningful tests and limitations. Add a changelog entry, run the validation checks, and commit.
6. Use release tags/commits in downstream projects; refresh when affected facts change.

Archive material is immutable provenance. Correct a claim in maintained guidance with a link to the original, never by silently altering the snapshot. Git blob deduplication retains equivalent archived paths; catalog deduplication merges exact URLs while retaining each provenance record.

The [official-source practice](official-source-build-practice.md) and [knowledge policy](knowledge-policy.md) govern evidence handling. Imported project gates, personnel and canceled operating rules do not govern this repository.
