# Levarum Squarespace Design & Build Guide

Living collaboration document · Working version 1.0

## Purpose

This is the practical document the owner and coach follow together while creating a new private Levarum Squarespace 7.1 site. It is subordinate to current explicit owner instructions and the governing Launch Control. It does not authorize purchases, publication, DNS changes, production data, or autonomous website editing.

## Working agreement

- The owner operates the editor unless explicitly requesting a bounded action.
- The coach gives one precise editor action at a time: Action, Why, Expected, Undo, Reply with.
- Every returned screen is inspected before the next action.
- Decisions, actual results, evidence, defects, and the next action are recorded here.
- Yesterday's unsuccessful site is owner-reported deleted and must not be restored or reused.
- The new site remains private until separate release approval.

## Success definition

Create an original, distinctive and professionally polished Levarum experience that clearly explains Game Plan → Build → Run, helps an owner-run business recognize useful automation opportunities, supports direct navigation, and includes a prominent real multi-turn assistant leading to a verified next step.

“Top 1%” is our ambition, not a publishable rank. Candidate-ready means an evidence-backed average of at least 8.5/10 across the ten quality categories, no category below 7, and mobile and accessibility at least 8.

## Decision 1 — How we start

All Squarespace 7.1 templates share the same underlying features and style options. The choice changes the starting composition and effort, not the design ceiling.

| Option | Advantage | Risk | Levarum fit |
|---|---|---|---|
| Designer template | Fast, composition already visible | Demo structure can make the result generic | Consider only if structure strongly matches our desired journey |
| Blueprint AI | Fast page and style scaffold | Generic copy and predictable sections can look finished too early | Use only as disposable scaffolding |
| Custom-guided 7.1 build | Maximum control over identity and rhythm | More decisions and manual layout work | Recommended default for the award-level ambition |

Current status: OPEN. First safe action is to browse templates without selecting one, compare up to three structural candidates, then consciously choose template or custom-guided.

## Design system sequence

| Wave | Design job | Squarespace surface | Proof before continuing |
|---|---|---|---|
| DS-01 | Choose one original art direction | Concept comparison outside or before editor | Owner selects direction using the quality rubric |
| DS-02 | Typography roles | Website → Design → Site styles → Fonts; verify live labels | Desktop/mobile wrapping and readable hierarchy reviewed |
| DS-03 | Color and section themes | Website → Design → Site styles → Colors | Contrast measured and themes assigned consistently |
| DS-04 | Button hierarchy | Website → Design → Site styles → Buttons | Primary/secondary/tertiary roles and focus states are clear |
| DS-05 | Spacing and section rhythm | Site styles plus page sections/Fluid Engine | Page has deliberate pacing at desktop and mobile |
| DS-06 | Header and navigation | Edit site header → Edit design | Contrast, active/hover/focus and mobile menu reviewed |
| DS-07 | Asset language | Image/video/background blocks and original assets | Rights, crops, alt text, weight and visual consistency reviewed |
| DS-08 | Motion grammar | Site styles → Animations plus supported block effects | Trigger, timing, end state, mobile, static and reduced motion reviewed |

## Native feature map

| Feature | Visual job | Class | Current documented path | Levarum use | Mobile/accessibility/performance/rollback |
|---|---|---|---|---|---|
| Fluid Engine grid, overlap and layers | Editorial composition and hierarchy | Native | Pages → page → Edit; arrange desktop/mobile separately | Asymmetric hero, workflow storytelling, layered proof | Preserve reading order; test overlap/crops; duplicate affected page/section before a large change |
| Global fonts | Brand voice and information hierarchy | Native | Website → Design → Site styles → Fonts | Distinct display voice with highly readable body text | Test wrapping/zoom/availability; record prior font pack |
| Color themes | Atmosphere, contrast and rhythm | Native | Website → Design → Site styles → Colors | Warm light fields, controlled accent and deep trust sections after approval | Measure contrast; record hex values and prior themes |
| Button presets | Action hierarchy | Native | Website → Design → Site styles → Buttons | One primary commercial action, secondary exploration, tertiary utility | Keyboard/focus/touch review; record prior settings |
| Site-wide animations | Entrance rhythm | Native 7.1 | Site styles → Animations | Use selectively after static hierarchy works | Test all pages and reduced motion; select None to remove |
| Block transforms | Depth and expressive asymmetry | Native on supported blocks | Block/Stack → pencil → Design → Transforms | Offset proof, rotated accents, layered imagery | Avoid text distortion; retune mobile; reset transform values |
| Header effects | Integrate navigation with page atmosphere | Native | Edit site header → Edit design → Color | Adaptive or controlled gradient only if contrast stays reliable | Test blur support and mobile menu; revert to solid |
| Image effects/crops/overlays | Consistent art direction | Native where supported | Image block → pencil → Design | Original process imagery or illustration, not generic stock default | Alt text, focal point, optimized files; remove effect/restore crop |
| Pinned/layered/collapsible content | Guided storytelling | Verify native availability/plan | Feature documented; exact live path unverified | Possible Game Plan → Build → Run narrative | Test native first, sticky/mobile/reduced motion; do not purchase extension without approval |
| Visitor assistant | Useful conversation and handoff | External service/server system | Provider-specific | Prominent Home entry plus accessible site-wide continuity | Consent, data, retention, text access, performance, honest receipts and rollback plan required |

## Build roadmap

1. Choose starting route without creating a site accidentally.
2. Create the new private trial and record its exact URL/title/privacy state.
3. Capture the untouched baseline and recovery approach.
4. Select one original Levarum design direction.
5. Establish global typography, color, buttons, spacing, header and footer.
6. Build and polish Home's static structure.
7. Add original asset direction and purposeful motion.
8. Compose and test Home mobile layout.
9. Extend the system to How It Works, What We Automate, Questions and Start.
10. Design the assistant states before choosing/configuring a provider.
11. Add the public Research hub and separately architect the secure Owner portal.
12. Run full QA and pause for explicit release decisions.
